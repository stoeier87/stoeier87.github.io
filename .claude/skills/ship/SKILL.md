# /ship

**The PR body is the review artifact in this repo.** There have been zero code reviews across 53 PRs and `main` is unprotected, so the body is the only durable record of why a change is correct. Write it accordingly — this is not a formality.

## Before writing anything

1. `npm run gates` — build, format, lint, typecheck.
2. `/verify` — you need a real check count and a real caveat.
3. `git diff main...HEAD --stat` and read your own diff. Anything you can't explain doesn't go in the PR.
4. Gather the **measured numbers**. Not "improved mobile layout" — document height at 375px before and after, pill width spread, element position deltas. If you have no numbers, go get them; the table is where this template earns its keep.

## The template

```markdown
Preview: `https://stoeier87.github.io/preview/preview/<topic>/`

## <Surface touched>

**<Root cause in bold, stated before the fix.>** <One or two sentences of prose
explaining the mechanism. Show the mismatch as code where you can.>

<What the change does about it.>

## <Next surface touched>

...

|                        | before | after  |
| ---------------------- | ------ | ------ |
| document height @375px | 5278px | 812px  |
| pill width spread      | ragged | 0px    |
| desktop journey        | 5901px | 5901px |

## Verification

Headless Chromium, **24/24 checks** at 1440×900 / 1280×800 / 390×844 / 375×812 /
360×640 / 320×568. <What was asserted.>

⚠️ <What you could NOT verify, named specifically.>

_Generated by [Claude Code](https://claude.ai/code/session_<id>)_
```

## What makes this template work — don't drop these

- **Preview URL on line one.** The reviewer looks at the site before the diff. Report the _real_ URL including the `preview/preview/` doubling, not the tidy one.
- **Root cause before fix, in bold.** PR #43 printed the mismatch directly — `data-planet="neptune"` in the HTML against `planetMap = { … neptun: 7 }` in the JS — then explained the consequence. Do that.
- **Say when it isn't a regression, and prove it.** "Not a regression from recent work — the last commit touching `arcade.js` before this is `2d8471f`, which predates it." Pre-empting blame saves a round trip.
- **A row that asserts what did _not_ change.** `desktop journey 5901px → 5901px`. Proving what you didn't break is a habit here and it's the row reviewers trust most.
- **A heading per surface.** Multi-page changes get one `##` per page, not one wall.
- **The `⚠️` caveat, honest.** Blocked fonts, no real touch hardware, no WebKit, Firebase not exercised. Hand back residual work by name: "Still missing: `og:image` — I didn't generate it because the brand fonts load from Google Fonts, which this sandbox blocks."
- **Superseding an earlier PR?** Say so explicitly: "Superseded by #45 — same commits, no work lost."

## Commit, if needed

House style, `CLAUDE.md` §5. Conventional Commits with page-level scope, `content:` for copy-only edits, a prose-judgment subject, a body explaining cause and measurement, `Co-Authored-By` naming your **exact model**, and a `Claude-Session:` URL. **No 🤖 line in commit messages** — that belongs in the PR body only.

## Then stop

Print the full `gh pr create --title … --body-file …` command and stop.

**Do not open the PR. Do not merge. Do not offer to merge.** `deploy.yml` has no `push` trigger, so merging a PR to `main` _is_ the production deploy — it publishes to `stoeier.dk` within a minute. That decision is the user's, every time.
